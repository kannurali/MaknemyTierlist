# Выделение предмета свечением

**Дата:** 2026-09-16, доработка 2026-09-17
**Ветки:** `feat/item-glow` (PR #71, только золото), `feat/item-glow-colors`
(три цвета)

## Задача

В окне редактирования предмета на тирлисте дать админу включить выделение:
небольшое свечение вокруг предмета, заметное посетителю.

## Решения владельца

Варианты показывались на живом тирлисте (скриншоты с реальными иконками).

- **Вид — свечение по контуру фрукта** (вариант A). Обводка ячейки,
  обводка со свечением и ореол за иконкой отклонены.
- **Цвета — на выбор: золотой, ярко-зелёный, ярко-красный.** В PR #71 был
  только золотой; зелёный и красный попросили добавить после мержа. Из двух
  показанных вариантов выбран насыщенный («ярче»), а не со светлым ядром.
- **Только на сайте, в PNG не попадает.** Экспорт не трогаем.

## Данные

Поле предмета `glow` хранит цвет свечения.

| Значение | Что видно |
|---|---|
| `"gold"`, `"green"`, `"red"` | свечение этого цвета |
| `true` | золото — так сохранял PR #71, такие предметы уже есть на сайте |
| `""`, `false`, нет поля, любое другое | без свечения |

- Разбор значения — одна функция `glowOf(item)` в `app.js`; все остальные
  места работают только с её результатом.
- Новый предмет (`addItem`, `defaultState`) создаётся с `glow: ""`.
- «Готово» пишет строку: старое `true` при первом же сохранении предмета
  становится `"gold"`. Отдельной миграции нет.
- Сервер не меняется: `save.php` проверяет только наличие массива `tiers`
  и размер, поля предметов не фильтрует.

## Редактор (`index.php`, `app.js`)

После поля «Тренд» — поле «Выделение»: сегмент `#mGlow` из четырёх кнопок.

| Кнопка | `data-v` | Классы |
|---|---|---|
| `—` | `""` | — |
| `✦ Золотое` | `gold` | `seg-glow glow-gold` |
| `✦ Зелёное` | `green` | `seg-glow glow-green` |
| `✦ Красное` | `red` | `seg-glow glow-red` |

- `openModal` ставит сегмент по `glowOf(it)`, «Готово» пишет
  `it.glow = getSeg("#mGlow")`.
- Переключение — общий обработчик простых сегментов
  (`["#mDemand", "#mTrend", "#mGlow"]`).
- Превью иконки в шапке окна (`.icon-preview`) получает классы
  `glow glow-<цвет>` сразу при нажатии и при открытии окна
  (`syncGlowPreview`) — админ видит цвет до сохранения.
- Подпись каждой цветной кнопки окрашена своим цветом.
- Подписи — в `i18n.js`, в обеих таблицах: `modal.glow`, `modal.glowGold`,
  `modal.glowGreen`, `modal.glowRed`, `modal.glowTitle` (подсказка: свечение
  видно на сайте, в PNG его нет). `modal.glowOn` из PR #71 убран.

## Тирлист (`app.js`, `styles.css`)

`renderCell` ставит ячейке классы `glow glow-<цвет>`, если `glowOf(item)`
не пуст.

Свечение — два слоя `drop-shadow` на иконке: ядро и ореол. Размеры общие для
всех цветов, цвет приходит из переменных `--glow-core` и `--glow-halo`.

| Ширина | Ядро | Ореол |
|---|---|---|
| компьютер | `.15cqw` | `.45cqw` |
| телефон, ≤640px | `.42cqw` | `1.27cqw` |

| Цвет | `--glow-core` | `--glow-halo` |
|---|---|---|
| золотой (`.glow`, `.glow-gold`) | `#ffe27f` | `rgba(255,190,40,.95)` |
| зелёный (`.glow-green`) | `#5dff6a` | `rgb(0,255,64)` |
| красный (`.glow-red`) | `#ff4a4a` | `rgb(255,0,0)` |

- Золото стоит и на голом `.glow`: класс без цвета остаётся золотым, как в
  PR #71. Правила зелёного и красного идут после — специфичность одна.
- Телефонные размеры — десктопные × 2,015 (ячейка 14cqw против 6,95cqw) × 1,4:
  при строго пропорциональном свечении на телефоне его почти не видно.
- Правило `.cell.glow .cell-icon img` стоит **после** блока наведения:
  специфичность у него та же, что у `.cell:hover .cell-icon img`, поэтому при
  наведении свечение остаётся своего цвета, а подъём ячейки и голубой фон под
  иконкой работают как у всех.
- Телефонное `.cell-icon img { filter: none; }` менее специфично и свечение не
  гасит.
- `var()` внутри `filter` поддерживают все движки, в Safari — с iOS 9.3.

## PNG

Без изменений. html2canvas 1.4.1 CSS-фильтры не рисует вовсе, поэтому
предмет выходит в PNG без свечения — ровно как решено.

## Чего не делаем

Легенда, превью ссылки (`og-tierlist.php`), калькулятор — без изменений.

## Ограничение

На iPhone каждое свечение — отдельный элемент с `filter`. Падения Safari в
августе лечили в том числе сокращением таких элементов (118 → 5, см.
`2026-08-03-safari-memory-and-i18n-design.md`). Свечение рассчитано на
единицы и десятки предметов, не на весь список.
