# Вход через Roblox по приглашению

**Дата:** 2026-09-17
**Ветка:** `feat/roblox-login-invite`

## Задача

OAuth-приложение «Maknemy» в Roblox не опубликовано. Пока его не одобрят,
войти могут только **10 разных аккаунтов**, 11-й получает отказ. На бою вход
ещё выключен: ключей в `config.php` нет. Как только их впишут, кнопку «Войти
через Roblox» увидят все посетители, и 10 мест разберут случайные люди. Тогда
владелец не успеет записать демо-видео для ревью (Roblox требует его в заявке),
а ревьюер не сможет войти сам.

## Решение владельца

До одобрения кнопку входа видят только те, кто открыл сайт по ссылке с
`?signin`. Эту же ссылку владелец ставит в Entry Link приложения:
`https://maknemy.com/?signin`. После одобрения одна строка конфига открывает
вход всем.

## Сервер

- `config.php`: новый ключ `roblox_login_public`, по умолчанию `false`
  (в `config.sample.php` так и записан).
- `api/lib/roblox_oauth.php`: `roblox_login_public(array $cfg): bool`. `true`
  только когда вход включён (`roblox_oauth_enabled`) и значение истинно по
  `FILTER_VALIDATE_BOOLEAN`. Конфиг правят руками в cPanel: строка `'false'`
  в кавычках не должна открыть вход, как открыла бы при `!empty()`, а `'true'`
  в кавычках — должна.
- `api/session.php`: в ответе новое поле `roblox_public`. Смысл `roblox` не
  меняется — «приложение заведено».
- `api/roblox_start.php` и `api/roblox_callback.php` не меняются. Приглашение
  решает, кому показать кнопку, а не кому разрешить вход. Случайный посетитель
  на `/api/roblox_start.php` сам не попадает, а серверная проверка потребовала
  бы своего состояния ради того же результата.

## Шапка (`js/topbar.js`)

- Приглашение — параметр `signin` в query, с значением или без, на любой
  позиции. `signinx`, `xsignin` приглашением не считаются.
- Шапка запоминает приглашение в `localStorage` (`nexus-signin-v1` = `"1"`)
  и убирает параметр из адреса через `history.replaceState`. Так ссылка не
  расходится копированием адреса, а `?return=` у кнопки входа остаётся чистым.
  Остальной query и `#hash` сохраняются.
- Приглашение разбирается после ответа `/api/session.php`, до всех проверок,
  поэтому параметр уходит из адреса при любом состоянии входа.
- Кнопка профиля становится ссылкой входа, если `roblox && !user &&
  (roblox_public || приглашён)`. Вошедший видит аватар с меню независимо от
  приглашения — иначе ему нечем было бы выйти.
- Без приглашения при закрытом входе шапка такая же, как сейчас: заглушка
  «В активной разработке».
- `localStorage` недоступен — приглашение действует только на странице,
  открытой по ссылке.

## Документация

README, раздел «Вход через Roblox»: ключ `roblox_login_public`, ссылка-
приглашение, Entry Link `https://maknemy.com/?signin`, что потребовала форма
ревью (демо-видео, категория Account Linking Tools с обоснованием) и что
сделать после одобрения. Таблица ручек: `{admin, user, roblox, roblox_public}`.

## Чего не трогаем

- Разметку кнопки профиля на страницах: заглушка `data-soon` остаётся.
- Серверные эндпоинты входа.
- PR #70 (профиль и чат). Его ссылки входа на `/chat` и `/profile` идут мимо
  приглашения — при мерже #70 их надо подчинить `roblox_public` так же.

## Проверка

- `tests/roblox_auth_test.php`: `roblox_login_public` на выключенном входе,
  без ключа, на `true`/`false` и их строковых записях; `handle_session`
  отдаёт `roblox_public`; ключ в `config.sample.php` равен `false`.
- `tests/topbar_test.php`: условие показа кнопки в `topbar.js` учитывает
  `roblox_public` и приглашение, ключ `nexus-signin-v1`, регулярка
  параметра, одна версия `topbar.js` на всех четырёх страницах.
- `tools/check-signin-invite-ui.mjs` (Playwright, `/api/session.php`
  подменяется):
  1. вход закрыт, приглашения нет — заглушка `button[data-soon]`;
  2. `?signin` — ссылка на `/api/roblox_start.php?return=…`, параметра в
     адресе больше нет, повторный заход без параметра — снова ссылка;
  3. вход открыт всем — ссылка без приглашения;
  4. вход выключен — заглушка даже с `?signin`;
  5. вошедший — аватар с меню;
  6. `?tab=1&signin=1#top` — адрес `?tab=1#top`, он же в `return`;
  7. `?signinx=1` — не приглашение, адрес не трогается;
  8. `localStorage` бросает — ссылка по приглашению есть, после перезахода
     без параметра её нет.
- `topbar.js?v=` 5 → 8 на четырёх страницах: PR #70 поднимает до 7.
