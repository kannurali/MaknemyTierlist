# Мультиязычный maknemy.com

Сейчас сайт знает два языка, RU и EN, и оба живут на одних и тех же адресах:
сервер всегда отдаёт русский HTML, а `js/i18n.js` после загрузки подменяет
тексты по `data-i18n`. Поисковик видит только русский, а язык выбирается
грубо — `pickLang()` даёт EN, только если язык браузера начинается с `en`.

Цель — европейская аудитория: у каждого языка свои адреса, сервер сразу
отдаёт страницу на нужном языке, первый заход сам попадает на язык браузера.
СНГ пока остаётся на русском.

## Принятые решения

| вопрос | решение |
| --- | --- |
| языки | ru (основной), en, de, fr, es, it, pt, pl, tr, uk |
| СНГ | русский; отдельные kk/uz/ky и т. п. не делаем |
| подход | сервер рендерит язык (не подмена в браузере, не сторонний сервис) |
| русский | остаётся на текущих адресах без приставки |
| реклама | как сейчас, без деления по языкам |

## 1. Адреса

- Русский: `https://maknemy.com/tierlist`, `/news/12` — ничего не меняется.
- Остальные: приставка с кодом языка ISO 639-1 — `/de/tierlist`,
  `/en/news/12`, главная `/de`. Слэш на конце — 301 на адрес без него, как
  у всех разделов сейчас (`/de/` → `/de`).
- Приставку снимает правило в начале `.htaccess` и передаёт язык в PHP
  переменной окружения; дальше срабатывают существующие правила разделов.
  Новых PHP-файлов на язык нет.
- Статика и API общие: страницы с приставкой обязаны иметь `<base href="/">`,
  чтобы `css/…`, `js/…`, `api/…` резолвились от корня и не плодили копий в
  кеше. Тест проверяет это для каждой публичной страницы.
- Приставка снимается только у известных разделов (главная, tierlist,
  calculator, profile, chat, trading, trading/new, stock, support,
  giveaways, ads, news, news/<id>). `/de/admin…`, `/de/api/…` и прочее —
  404. Админка только по-русски.
- Юридические страницы (`/privacy`, `/terms`) уже двуязычные — русский и
  английский текст на одной странице — и остаются без приставки: их адреса
  вписаны в карточку OAuth-приложения Roblox. `/<код>/privacy` → 301
  `/privacy`.
- Португальский — бразильский вариант (основная португалоязычная аудитория
  Blox Fruits), испанский — нейтральный; в hreflang просто `pt` и `es`.

## 2. Сервер отдаёт язык

**Словари.** Строки переезжают из `js/i18n.js` в `public_html/lang/<код>.json`
(плоский объект `ключ → строка`, те же ключи, что сейчас). Это единственный
источник текстов интерфейса и для PHP, и для JS.

**`t()` в PHP.** `api/lib/i18n.php`: язык запроса (из переменной окружения,
по умолчанию `ru`), `t($key, $vars = [])` с подстановкой `{name}`, откат
`язык → en → ru → сам ключ` — так же, как `I18N.t()` сейчас.

**Шаблоны.** ~770 мест с `data-i18n*` в PHP-страницах переводятся на `t()`
скриптом: текст элемента и атрибуты `title/aria-label/placeholder/alt`
берутся из словаря. Атрибуты `data-i18n*` остаются — по ним JS находит
элементы, которые обновляет сам. Защита от поломок: русская версия каждой
страницы до и после замены совпадает байт в байт (снимки на тестовой базе).

**Голова страницы.** Сервер ставит `<html lang>`, `<title>`, description,
`og:locale` + `og:locale:alternate`, canonical на свой же адрес и блок
hreflang на все 10 версий плюс `x-default` → русская. Тексты голов — тоже
ключи словаря.

**Ссылки.** Внутренние ссылки на нерусских страницах ведут на свою
приставку: PHP — `u('/tierlist')`, JS — `I18N.url('/trading')`. Внешние
ссылки и ссылки в Telegram-бота не трогаются.

**sitemap.xml** перечисляет все языковые версии каждого раздела с
`xhtml:link rel="alternate" hreflang`.

**Что переводится позже.** Разметка Schema.org (JSON-LD) в PR 1 выводится
только на русских страницах, перевод — в PR 2. Превью, собранные из данных
(og:title тирлиста с тиром и датой, превью поста), переводятся в PR 3 вместе
с контентом.

## 3. JS

- `js/i18n.js` остаётся маленьким API: `t()`, `url()`, язык страницы берётся
  из `<html lang>`, а не из `localStorage`.
- Словарь страница получает отдельным файлом своего языка
  `js/i18n/<код>.js?v=N` — статический, кешируется на год, как весь js.
  Файлы собирает `php tools/i18n_build.php` из `lang/*.json`, откат
  `язык → en → ru` уже вшит в собранный файл. Тест сверяет, что собранные
  файлы совпадают со словарями.
- Живого переключения языка на странице больше нет: выбор языка — переход
  на адрес другого языка.
- Переходный период: у кого в `localStorage` (`nexus-lang-v1`) записан `en`,
  а куки выбора ещё нет, JS один раз ставит куку `nx_lang=en` и переходит на
  `/en/…`.

## 4. Автоопределение и выбор

Правило в `.htaccess`, до кеша LiteSpeed (кеш отдаёт страницы мимо PHP,
поэтому решать в PHP нельзя). Работает только на адресах без приставки:

1. Поисковые и превью-боты (Googlebot, bingbot, YandexBot, TelegramBot,
   Discordbot, facebookexternalhit и т. п.) — никогда не перенаправляются.
2. Есть кука `nx_lang`: `ru` — остаёмся; другой язык — 302 на его приставку.
3. Куки нет — первый язык из `Accept-Language`:
   - de/fr/es/it/pt/pl/tr/uk/en → 302 на `/de/…` и т. д.;
   - ru и языки СНГ (kk, uz, ky, be, az, hy, ka, tg, tk) → остаёмся;
   - любой другой → `/en/…`.

Адрес с приставкой не перенаправляет никогда. Перенаправление — 302 (не
301), чтобы браузер его не запоминал.

**Переключатель.** Выбор ставит `nx_lang` на год (с `Secure` только по
https) и переводит на тот же раздел на новом языке. В PR 1 это прежние
чипы RU/EN. В PR 2, когда языков станет больше двух, их место займёт список
на своих названиях (Русский, English, Deutsch, Français, Español, Italiano,
Português, Polski, Türkçe, Українська); визуал — через дизайн-агента.

## 5. Контент

**Интерфейс** (~840 строк × 8 новых языков) переводит Claude, по ключам и с
учётом сленга Blox Fruits (перм, трейд, демант, сток). Тест: во всех языках
одинаковый набор ключей, одинаковые подстановки `{…}`, нет пустых строк.

**Новости, розыгрыши, описания предметов.**
- EN при сохранении — как сейчас (`api/lib/translate.php`), ручной EN не
  трогается.
- Остальные 8 языков переводятся с русского после ответа на сохранение, в
  фоне (`fastcgi_finish_request()` / `litespeed_finish_request()`), тем же
  Google-эндпоинтом. `translate.php` получает целевой язык параметром вместо
  константы `tl=en`.
- Хранение — таблица `i18n_texts (kind, ref_id, field, lang, src_hash,
  text, updated_at)`, ключ `(kind, ref_id, field, lang)`. `src_hash` —
  хеш русского текста: перевод старой версии не показывается. Миграция
  `<дата PR 3>-i18n-texts.sql` после мержа.
- Пока перевода нет или Google отказал — показывается EN, без него RU.
- `php tools/i18n_backfill.php` дозаполняет недостающие переводы — им же
  переводится всё уже опубликованное при запуске.
- В выдачу (`api/news.php`, `api/tierlist.php`, `api/giveaways.php`) попадает
  только язык страницы, параметром `lang`; правила `.htaccess` на query string
  этих эндпоинтов расширяются под него.

**Не переводим:** чат, объявления, ники, Telegram-бот и его рассылки,
рекламные креативы, админку.

## 6. Шрифты

Проверено по таблицам символов:

| шрифт | где | чего нет |
| --- | --- | --- |
| Bootshaus | `--display`, 223 места | турецкой `ı` |
| Proto Sans | `--proto`: текст новостей, 2 места тирлиста | любой латиницы с диакритикой (`ä é ñ ç ł …`) |
| Oswald | профиль, шапка, юр. страницы | загружены только наборы latin и cyrillic |

- На нерусских и неанглийских страницах `--proto` указывает на Bootshaus
  (через `:lang()`), иначе `ä é ñ` выпадут в Arial Narrow посреди слова.
- Для Oswald добавляется набор latin-ext (польский, чешский, турецкий).
- Для `:lang(tr)` в стек `--display` сразу после Bootshaus добавляется
  Oswald latin-ext — из него браузер возьмёт `ı`.
- Правки `css/*.css` дублируются в `css/hw/` (`php tools/halloween_css.php`),
  версии `?v=` поднимаются.

## 7. Порядок работ — 3 PR

1. **Основа.** `lang/ru.json`, `lang/en.json`, `t()`, шаблоны на `t()`,
   приставки и `.htaccess`, головы и hreflang, sitemap, автоопределение,
   чипы RU/EN ведут на адрес языка, `js/i18n/*.js`. Включены только ru и
   en: английский переезжает на `/en/…`. Миграций нет.
2. **Языки.** Словари de, fr, es, it, pt, pl, tr, uk; список языков вместо
   чипов; JSON-LD на всех языках; шрифты; проверка вёрстки на всех языках.
3. **Контент.** `i18n_texts`, фоновый перевод, backfill, `lang` в API.
   Миграция после мержа.

## 8. Проверка

- `tests/i18n_test.mjs`: паритет ключей и подстановок, собранные
  `js/i18n/*.js` совпадают со словарями.
- PHP-тесты: `t()` и откат, язык из окружения, блок hreflang, `u()`.
- Снимки русской версии всех публичных страниц до и после PR 1 — байт в
  байт.
- Правила `.htaccess` (приставки, автоопределение, боты, куки) — на
  локальном Apache, все ветки из раздела 4.
- PR 2: Playwright-скриншоты всех публичных страниц × 10 языков × компьютер
  и телефон, автоматическая проверка переполнения (`scrollWidth > clientWidth`
  у текстовых блоков).
- На бою после мержа PR 1: правило автоопределения срабатывает раньше
  LSCache; `/tierlist` и `/en/tierlist` кешируются раздельно; hreflang через
  curl; адреса в Search Console.

## Риски

- **Порядок `.htaccess` и LSCache.** Если на бою кеш отвечает раньше
  правила — автоопределение переносится в JS (`location.replace` на русской
  странице при первом заходе), остальное не меняется.
- **Длина текста.** Макет пиксельный, Bootshaus узкий, немецкие и польские
  слова длинные. Нужны `overflow-wrap`/`hyphens` в тесных местах — найдёт
  проверка PR 2.
- **Google-эндпоинт** бесплатный и без договора: 8 языков на каждое
  сохранение могут упереться в лимит. Откат на EN, догон — backfill.
- **Новые страницы для поиска** первое время тонкие: на них только интерфейс
  и переведённый контент. Позиции вне РФ появятся не сразу.

## Вне рамок

- Деление рекламных кампаний по языкам.
- Перевод Telegram-бота.
- Языки СНГ кроме русского.
- Ручная правка переводов кроме EN в админке.
