# Перенос макета «макнеми тир под сайт» на сайт

Дата: 2026-08-05
Ветка: `feat/design-2026-08` (от `origin/master` @ `d4eac0e`)

## Задача

Воспроизвести на сайте новую редакцию постера-макета. Источники:

- `~/Downloads/макнеми тир под сайт.png` — 1523×2486, сведённый макет;
- `~/Downloads/макнеми тир под сайт.psd` — тот же макет послойно, откуда берутся
  ассеты, точная геометрия и типографика.

Предыдущая редакция того же шаблона лежит в репозитории как
`public_html/assets/template.png` (заголовок «NEXUS TIER LIST»). Сайт собран
по ней, поэтому новая редакция — правка существующей вёрстки, а не переделка.

## Что меняется относительно текущего сайта

1. Плашка тира с логотипом превращается в **карточку автора**: роль, `@ник`,
   логотип, комментарий.
2. **Легенда** перестраивается из пяти колонок в три блока и получает строку
   «новый».
3. **Подвал** получает круглую аватарку у каждой ссылки.
4. **Заголовок** переезжает на Proto Sans, «MAKNEMY» и «TIER LIST» получают
   разные кегли. В шапке 💧 меняется на ⚡.
5. Чинится глиф «Й» в шрифте Bootshaus.

Дорожки предметов, фон, лепестки, значки предметов, реклама, донат, модалки и
тулбар не трогаются.

## Единица пересчёта

Контент-колонка макета — от x=135 до x=1423, ширина 1288 px. В вёрстке она
равна ширине сцены минус горизонтальные паддинги: `100cqw − 2 × 2.6cqw =
94.8cqw`. Отсюда

```
1 px макета = 94.8 / 1288 = 0.0736 cqw
```

Все размеры ниже получены этим пересчётом из координат PSD и округлены до
сотых cqw. Ни одно значение не подобрано на глаз.

## Схема данных

### Тир

Тир получает необязательный объект `card`:

```js
{
  id, label, logo, items: [...],
  card: {
    role:    "Владелец",
    handle:  "@mksvtn",
    comment: "за деньги не продаюсь 🥶\nмаксимум за рокет 🚀"
  }
}
```

Правила:

- Карточка рисуется, если у тира **есть и `logo`, и непустой `card`**. Иначе
  плашка рендерится как сейчас: логотип по центру либо текстовый заголовок.
- Логотип карточки — существующее поле `logo`. Второе поле под картинку не
  заводится.
- `comment` — многострочный текст, перенос по `\n`, ограничение 2 строки.
- Состояние без `card` грузится и работает. Это же гарантирует, что старые
  записи в БД и импортированные JSON не ломаются.

### Ссылка подвала

```js
{ title, sub, href, icon }
```

`icon` — путь к картинке либо пустая строка. Пустой `icon` рисует ссылку без
аватарки, сетка при этом не разъезжается.

### Титры

`state.credits` остаётся как есть. Нижняя полоска титров сохраняется для тех,
кому не досталось карточки (решение раздела «Титры» ниже).

### Миграция существующего состояния

В боевой базе сейчас три тира с логотипами (`MK`, `GLH`, `💧`), ни у одного нет
поля `card`. Без миграции после деплоя не появится ни одной карточки, а дизайн
проявился бы только после ручного заполнения админом. Поэтому:

1. `defaultState()` в `public_html/js/app.js:39` получает карточки у трёх
   логотипных тиров и `icon` у ссылок подвала — с содержимым из макета.
2. Одноразовая миграция в `tools/`: для каждого тира с логотипом, у которого
   нет `card`, поле проставляется по соответствию логотипа человеку —
   `logo-mk` → владелец, `logo-glh` → аналитик, `logo-bolt` → дизайнер.
   Роли, ники и тексты комментариев берутся из PSD: они уже извлечены как
   текстовые слои и не набираются заново.
3. Тир `💧` меняет логотип на `logo-bolt.png` — в макете третья карточка
   помечена молнией, а не пламенем.
4. Ссылкам подвала проставляется `icon` по совпадению `title`. Ссылка, для
   которой аватарки в макете нет («Сайт сделал»), остаётся без иконки —
   это рабочее состояние, а не ошибка.

Миграция идемпотентна: повторный запуск ничего не меняет, потому что заполняет
только пустые поля. Существующие правки админа не затираются.

### Миграция картинок

`card` не содержит картинок: логотип карточки — это `tier.logo`, который уже
обходится. А вот `footer[].icon` — новая картинка, и здесь первая версия спеки
ошибалась.

`walk_state_images` (`public_html/api/lib/images.php:121`) **не** обходит
состояние рекурсивно: она перечисляет пути явно — `tiers[].logo`,
`tiers[].items[].icon` и `ad.image`. Аватарки подвала в этот список не входили,
то есть не проходили бы ни даунскейл до `ICON_MAX_SIDE = 256` при загрузке, ни
`downscale_stored_images` при миграции, и картинка с телефона легла бы
в состояние в исходном разрешении.

Поэтому в обходчик добавляется ветка по `footer[].icon`, а тесты
`images_test.php` закрывают оба пути — загрузку data-url и миграцию уже
сохранённого файла.

## Карточка автора

### Структура

Внешний контейнер — существующая `.tier-band` со своим точечным фоном и
скруглением. Высота при наличии карточки: **4.6cqw → 8.24cqw**.

Внутри CSS Grid в три колонки:

```
│←──── 42.25cqw ────→│←─ 11.56cqw ─→│←──── 41.00cqw ────→│
┌────────────────────┐              ┌────────────────────┐
│           ВЛАДЕЛЕЦ │              │ КОММЕНТАРИЙ        │  2.80cqw
├────────────────────┤    логотип   ├────────────────────┤  0.44cqw зазор
│        @mksvtn  ✈  │              │ за деньги не …     │  4.93cqw
└────────────────────┘              │ максимум за рокет  │
                      ↑ звенья 0.29cqw по обеим сторонам разрыва
```

Сумма колонок: 42.25 + 11.56 + 41.00 = 94.81cqw — вся контент-колонка.

- Левая панель прижата к правому краю (`text-align: right`), правая — к левому.
- Логотип центрируется в разрыве, фона под ним нет.
- «Звенья» — вертикальные полосы шириной 0.29cqw по обеим сторонам разрыва,
  во всю высоту карточки, цвет `#F5F5FF`.
- Обе панели светлее внешней плашки и имеют тонкую светлую рамку. Заливка
  берётся из существующих токенов `.tier-band`, новые цвета не вводятся.

### Типографика

| Элемент | Шрифт | Кегль | Цвет |
|---|---|---|---|
| Роль (`ВЛАДЕЛЕЦ`) | Proto Sans | 1.91cqw | `#fff` |
| `КОММЕНТАРИЙ` | Proto Sans | 1.91cqw | `#fff` |
| `@ник` | Bootshaus | 2.29cqw | `#fff` |
| Текст комментария | Bootshaus | 2.29cqw | `#fff` |

Роль и слово «КОММЕНТАРИЙ» набраны в верхнем регистре через
`text-transform: uppercase`, чтобы в состоянии хранился человеческий регистр.

### Размеры вложенных картинок

| Ассет | PSD | cqw |
|---|---|---|
| Логотип MK | 131×83 | 9.64 × 6.11 |
| Логотип GLH | 116×48 | 8.54 × 3.53 |
| Логотип ⚡ | 94×86 | 6.92 × 6.33 |
| Иконка Telegram | 40×34 | 2.94 × 2.50 |

Логотип вписывается в разрыв по `max-width` / `max-height`, а не задаётся
жёстко: у разных тиров логотипы разной пропорции.

### Редактирование

Админ правит роль, ник и комментарий прямо на странице — тем же механизмом
`contenteditable` + `blur`, что и остальные подписи. Селекторы добавляются
в список на `public_html/js/app.js:1324`. Комментарий многострочный, поэтому
Enter в нём вставляет перенос, а не завершает правку; завершение — по уходу
фокуса.

Логотип карточки грузится существующей кнопкой смены логотипа тира.

Копи-защита (`body.protected`) не мешает: `[contenteditable="true"]` уже
исключён из запрета выделения, а админу защита снимается целиком.

## Легенда

Панель: 1288×189 px → высота 13.91cqw.

Три блока вместо нынешних пяти колонок:

| Блок | Содержимое | Раскладка |
|---|---|---|
| 1 | Бейджи типов | 2 колонки × 3 строки: `F / S / M` и `P / GP / CR` |
| 2 | Заголовок + спрос | заголовок сверху, под ним 2 колонки × 2 строки точек |
| 3 | Состояния | 1 колонка × 5 строк |

Заголовок «ПОМОЩЬ ДЛЯ НОВЕНЬКИХ» центрируется **над вторым блоком**, а не над
всей панелью: в PSD он занимает x 692→969, второй блок — x 696→966. Это
совпадение до 4 px, а не случайность.

Третий блок растягивается на всю высоту панели (`justify-content:
space-between`), первый и второй центрируются по вертикали.

Новая строка — **«новый»** с плашкой `new`. Порядок строк третьего блока
сверху вниз: под вопросом, рост, перерасмотр, упадок, новый.

Кегли: заголовок 2.4cqw → **2.82cqw**, строки 1.7cqw → **1.96cqw**.

Существующая строка «под вопросом» использует CSS-плашку `.lg-wip` и остаётся
такой. Строка «новый» получает свою CSS-плашку по образцу `.cell-new`, чтобы не
плодить картинки.

## Подвал

Панель: 1288×164 px → высота 12.07cqw.

Сетка 3 колонки, шаг колонки 331 px → **24.36cqw**, шаг строки 62 px →
**4.56cqw**. Отступ панели слева 58 px → 4.27cqw, сверху 39 px → 2.87cqw.

Каждая ссылка — круглая аватарка **3.39cqw** слева, справа два ряда текста:

| Элемент | Шрифт | Кегль | Цвет |
|---|---|---|---|
| Заголовок | Bootshaus | 1.94cqw | `#00F7FF` |
| Подпись | Bootshaus | 1.94cqw | `#fff` |

Зазор между аватаркой и текстом — 0.44cqw.

В макете пять ссылок, в живой БД шесть. Список остаётся управляемым из
состояния: сколько ссылок в `state.footer`, столько и рисуется. Шестая занимает
свободную клетку сетки. Данные не удаляются.

Каждый ассет сохраняется в PNG с прозрачностью и в WebP. Логотипы карточек
отдаются не крупнее 256 px по длинной стороне.

**Ограничение источника.** Четыре аватарки из пяти лежат в PSD растровыми
слоями 48×48 — оригинала крупнее нет. Аватарка рисуется 3.39cqw, это ~35 px
при ширине сцены 1040 px, то есть исходника хватает ровно на 1.4×. На экранах
с удвоенной плотностью аватарки будут слегка мягкими. Увеличивать их
интерполяцией бессмысленно, поэтому кладём как есть; если дизайнер отдаст
оригиналы, замена сведётся к подмене файлов.

Скрипт извлечения кладётся в `tools/extract-psd-assets.py` и коммитится, чтобы
повторный экспорт при правке макета не делался руками. PSD в репозиторий
**не** кладётся — он весит 133 МБ; путь к нему скрипт принимает аргументом.

## Производительность

Требование: не добавить лагов. У проекта есть история выброса текстур в Safari
на iOS, разобранная в `docs/superpowers/specs/2026-08-03-safari-memory-and-i18n-design.md`,
и выводы из неё записаны прямо в CSS.

Бюджет изменения: **+9 новых картинок** (`brand-logos.png` заменяется, а не
добавляется), **+0 слоёв композитинга, +0 фильтров.**

Правила, обязательные к соблюдению:

1. **Никаких `filter: drop-shadow`** на аватарках, логотипах карточек и иконке
   Telegram. Это 9 повторяющихся элементов; каждый `drop-shadow` заставляет
   WebKit заводить отдельную поверхность и размывать её альфу. Обоснование уже
   записано в `public_html/css/styles.css:707-717`.
2. **Никаких `backdrop-filter`, `mix-blend-mode` и `opacity < 1`** на
   контейнерах карточки и панелей. Причина — `public_html/css/styles.css:430-440`.
3. Прозрачность, если она нужна визуально, задаётся через `rgba()` в заливке,
   а не через `opacity` на элементе.
4. У всех новых `<img>` проставлены `width` и `height` — против сдвигов
   лейаута при загрузке.
5. `loading="lazy"` **не ставится**: экспорт в PNG через html2canvas требует,
   чтобы картинки уже были декодированы.
6. Карточка не увеличивает число узлов сверх нынешней плашки: тот же
   `.tier-band`, внутри Grid вместо одного `<img>`.

Оценка добавленной декодированной памяти: 5 аватарок 48² + 3 логотипа не
крупнее 256² + иконка Telegram 40×34 ≈ **0.9 МБ** при худшем раскладе, когда
все три логотипа упираются в потолок. Для сравнения, один снятый ранее слой
прозрачности стоил 30 МБ на iPhone.

Проверка — раздел «Тесты», пункт про измерение высоты страницы и числа
остановок при прокрутке.

## Адаптив

На `max-width: 640px` карточка в три колонки нечитаема: при ширине экрана
390 px на комментарий остаётся ~170 px. Карточка перестраивается в две строки:

```
┌─────────────────────────────────┐
│  [лого]   ВЛАДЕЛЕЦ  @mksvtn ✈   │
├─────────────────────────────────┤
│  за деньги не продаюсь 🥶       │
│  максимум за рокет 🚀           │
└─────────────────────────────────┘
```

Высота 8.24cqw → 16cqw. Кегли масштабируются пропорционально остальным
мобильным правилам, живущим в медиазапросе с 1121 строки.

Подвал на телефоне остаётся в одну колонку с аватарками; легенда сохраняет три
блока, но третий переносится под первые два.

## Починка «Й»

### Причина

В `assets/fonts/Bootshaus/Bootshaus-Regular.ttf` глиф `uni0419` (Й) — композит
из `uni0418` + `breve`, а `uni0418` (И) сам композит из `N`. Вложенность
второго уровня Skia не разворачивает: базовая буква теряется, остаётся одна
надстрочная дужка. Воспроизведено на голой странице с единственным
`@font-face`, без участия остального кода. Proto Sans тем же текстом
рисуется правильно.

Сейчас на сайте видно: `ПРОВЕРЯ˘ТЕ ЦЕНЫ НА СА˘ТЕ`, `МО˘ ТЕЛЕГРАМ`,
`ДИЗА˘НЕР`.

Затронуто 8 глифов: `onequarter`, `onehalf`, `threequarters`, `uni0419`,
`uni040D`, `Ohungarumlaut`, `Uhungarumlaut`, `Ldot`.

### Решение

Разворачиваем композиты в простые контуры через `fontTools`. Скрипт кладётся
в `tools/flatten-font-composites.py`, пересобранный шрифт коммитится.

Вариант «подменить шрифт для двух кодовых точек через `unicode-range`»
отвергнут: у Bootshaus и Proto Sans разная ширина и рисунок, «Й» посреди слова
выглядел бы вставкой из другого шрифта.

Правка обязательна, а не факультативна: слово «КОММЕНТАРИЙ» встречается
в карточках трижды.

## Титры

Макет не содержит нижней полоски титров — команда переехала в карточки. Но
карточек три (владелец, аналитик, дизайнер), а в состоянии пять человек:
добавляются «Помощник аналитика» и «Кодер сайта».

Буквальное копирование стёрло бы двоих со страницы. Решение: **полоска титров
сохраняется** и показывает тех, кому не досталось карточки. Это единственное
намеренное отступление от макета, и оно ограничено одной строкой внизу.

Логика: из `state.credits` при отрисовке исключаются роли, уже показанные
в карточках (сравнение по нормализованной роли). Если исключены все —
секция не рендерится, и страница совпадает с макетом.

| `tests/migrate_test.mjs` (новый) | миграция проставляет карточки по логотипу, меняет пламя на молнию, не трогает чужие логотипы, идемпотентна и не затирает правки админа |
| `tests/migrate_test.mjs` (новый) | аватарки подбираются по заголовку ссылки; ссылка без пары остаётся без аватарки |

Достройка состояния вынесена в `public_html/js/migrate.js` отдельным модулем по
образцу `i18n.js`. Внутри IIFE в `app.js` её нельзя было бы проверить из node —
только через браузер, а это уже не юнит-тест.

Регрессионный смысл `font_test.mjs`: этот тест провалился бы на нынешнем
шрифте, то есть поймал бы баг, который сейчас на проде.

Визуальная проверка — скриптом Playwright: снимок сцены на 1040 px и 390 px,
сравнение с макетом по ключевым блокам. Скрипт кладётся в `tools/`, снимки
в репозиторий не коммитятся.

Проверка производительности: до и после мерять высоту страницы и число
остановок при прокрутке тем же способом, что применялся в работе над Safari,
и убедиться, что показатели не ухудшились.

## Что не делается

- Дорожки предметов, значки, точки спроса, тренды — без изменений. Светлые
  точечные прямоугольники в макете это заглушки под контент, а не новый стиль:
  в предыдущей редакции шаблона они точно такие же.
- Фон, лепестки, «булыжник» и цветокоррекция из PSD не переносятся: сцена уже
  собрана по этому фону.
- Реклама, донат, модалки, тулбар, авторизация, лайки — вне задачи.
- Эмодзи в комментариях рисуются системным шрифтом. В макете они из набора
  Telegram; тащить их картинками ради трёх строк не стоит потери
  редактируемости текста.
