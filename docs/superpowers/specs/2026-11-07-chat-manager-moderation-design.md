# Чат-менеджер, этап 1: модерация

Дата: 2026-11-07. Статус: дизайн согласован, ждёт проверки спеки.

## Зачем

Наш бот (уведомления, посты в каналы, розыгрыши) в группах сейчас молчит:
`tg_handle_update()` отвечает только в личке. Владелец хочет, чтобы бот умел
управлять группами, как чат-менеджеры уровня «Ириса»: ранги, наказания,
фильтры, приветствие, репорты и прочее.

Работа разбита на три этапа, у каждого своя спека, план и PR:

1. **Модерация** — эта спека.
2. **Активность** — статистика и топы, профиль, репутация, награды.
3. **Игры и отношения** — дуэли, кубы, браки, кланы, рандом-команды.

Экономика (валюта, VIP, биржа) — возможно, позже, сюда не входит.

## Решения владельца

- Работает в **любой группе**, куда добавят бота. Чат настраивается командами
  прямо в группе, админка сайта для чужих чатов не нужна.
- Только **русский** язык: и команды, и ответы.
- **Тот же бот**, отдельный модуль (не второй бот и не отдельный сервер).
- Сам, без команды модератора, бот реагирует только на две вещи: **ссылки**
  (удаляет) и **спамеров из общей базы** (банит). Всё остальное — мат, флуд,
  капс, пересылки, медиа, приветствие — включает модератор командой.
- Сверх основы в этап входят: общая база спамеров, чистка чата, заметки,
  таймеры. Голосования за бан нет.

## Устройство

### Поток апдейта

`api/tg_webhook.php` получает апдейт и, если он из группы или супергруппы
(`message`, `edited_message`, кнопка с `callback_data`, начинающимся на `cm:`),
отдаёт его `cm_handle_update()` в собственном `try/catch`. Ошибка модуля
пишется в лог и не мешает остальной цепочке: розыгрыши (`gw_*`), список
каналов, личка (`tg_handle_update`) работают, как раньше.

Апдейты лички и кнопки розыгрышей в модуль не попадают. `my_chat_member` по-
прежнему разбирает `gw_channel_update()`; модуль дополнительно читает его,
чтобы завести или погасить строку чата.

Ответ из одного вызова уходит прямо в теле ответа вебхука (как `/start`
сейчас). Если действий несколько (удалить + замутить + написать), вебхук
сначала отдаёт 200 через `tg_finish_response()`, затем модуль делает вызовы
через `tg_http()`.

### Модули `public_html/api/lib/cm/`

Каждый файл — одна задача, общаются через функции с явными параметрами
(`PDO`, `$send`, `$now`), как остальной код бота. `$send` — тот же вызываемый
объект, что возвращает `tg_http()`, в тестах подменяется записью вызовов.

| Файл | Задача |
| --- | --- |
| `core.php` | `cm_handle_update()`, `cm_ready()`, учёт автора, бюджет сообщений, отправка |
| `parse.php` | разбор команды: префикс, слово, цель, срок, причина |
| `ranks.php` | ранги 0–5, создатель, журнал, доступ к командам (`дк`) |
| `punish.php` | варн, мут, кик, бан, снятие, списки, лимит варнов |
| `filters.php` | фильтры и триггеры |
| `words.php` | встроенный список матерных корней и исключений |
| `welcome.php` | приветствие и правила |
| `reports.php` | репорты и кнопки по ним |
| `spam.php` | общая база спамеров |
| `cleanup.php` | чистка сообщений и массовые кики |
| `notes.php` | заметки |
| `timers.php` | таймеры |
| `queue.php` | автоудаление служебных ответов |
| `texts.php` | все тексты ответов |

`api/cm_cron.php` — запуск раз в минуту: таймеры, автоудаление, очистка
`cm_msgs` старше 48 часов.

Нормализация слов (двойники букв, «0→о», «й→и», `*` по краям) и поиск ссылок
берутся из готового `api/lib/chat_filter.php`. Если для этого нужно вынести из
него функцию, она выносится без изменения поведения фильтра сайта.

### Нагрузка

- `setWebhook` получает `max_connections = 10` (`tg_setup_webhook()`), к
  `allowed_updates` добавляется `edited_message`.
- `'cm_enabled' => false` в config выключает модуль целиком. По умолчанию
  модуль включён, если таблицы на месте (`cm_ready()`, как `tg_ready()`).
- На каждое сообщение группы — обновление `cm_members.last_seen`, `cm_users` и
  одна строка `cm_msgs`. Остальные записи только по событию.

## Команды

### Как бот узнаёт команду

- Префикс `!`, `.` или `/` необязателен. Без префикса команда срабатывает,
  только если вся первая строка разбирается как команда.
- Если ранга не хватает, бот отвечает об этом только на команду с префиксом.
  Без префикса он молчит: обычное «бан бы ему» в разговоре ничего не вызывает.
- Команды уровня 0 без префикса срабатывают, только если первая строка —
  ровно команда («правила», «кто я»), без лишних слов. Исключение — `репорт`:
  он работает только ответом на сообщение, и без префикса тоже срабатывает с
  причиной («репорт спам»), раз ответ уже отсекает случайные совпадения.
- `/команда@ИмяБота` тоже понимается.

### Цель

По старшинству: ответ на сообщение → упоминание без ника (`text_mention`, в
нём сразу есть пользователь) → `@ник` (ищется в `cm_users`) → числовой id →
ссылка `t.me/ник`. Ника нет в `cm_users` — бот просит ответить на сообщение
человека.

### Срок

`30с`, `10м`/`10 минут`, `2ч`/`2 часа`, `3д`/`3 дня`, `неделя`/`2 недели`,
`месяц` (30 дней), `год` (365 дней), `навсегда`. Без срока: мут — 1 час, бан —
навсегда. Telegram считает срок меньше 30 секунд или больше 366 дней
бессрочным; бот такие сроки не принимает, кроме слова «навсегда».

### Причина

Всё после срока на той же строке или со второй строки, до 500 символов.

### Ранги

| Ранг | Название |
| --- | --- |
| 0 | участник |
| 1 | младший модератор |
| 2 | старший модератор |
| 3 | младший администратор |
| 4 | старший администратор |
| 5 | создатель |

- Создатель группы в Telegram — ранг 5 автоматически. Его id берётся из
  `getChatAdministrators` при добавлении бота и обновляется, если прошло больше
  суток, в момент проверки ранга.
- Админ Telegram и ранг бота — разные вещи: админ без ранга имеет ранг 0, но
  его не трогают фильтры, и наказать его бот не может (это запрещает Telegram).
- Назначить можно только ранг ниже своего. Наказать, понизить или снять можно
  только того, у кого ранг ниже твоего.
- Ранг 5 переходит только через `передать создателя`. Создатель группы в
  Telegram всегда может вернуть себе 5 командой `вернуть создателя`.
- Каждое изменение ранга пишется в `cm_rank_log`.

### Варны

- По умолчанию: лимит 3, срок жизни 30 дней, на лимите — бан 7 дней.
  Истёкший варн не считается; хранится как история.
- Набрал лимит — срабатывает триггер `варны` (та же настройка, что
  `варны наказание`), активные варны после этого снимаются.

### Мут, кик, бан

- Мут — `restrictChatMember` без права писать, бан — `banChatMember`, оба с
  `until_date`. Срок снимает сам Telegram, cron для этого не нужен.
- Кик — `banChatMember` и сразу `unbanChatMember` (человек может вернуться).
- `размут` / `разбан` снимают ограничение в Telegram и ставят `lifted_at`.
- `муты` / `баны` — активные записи `cm_punishments` этого чата.

### Репорты

- `репорт причина` в ответ на сообщение — может любой, не чаще раза в 5
  минут на человека в чате. Жаловаться на ранг ≥ 1 нельзя.
- По умолчанию жалоба выходит в той же группе: «⚠️ Жалоба от А на Б: причина»,
  ссылка на сообщение и кнопки «Удалить», «Мут 1ч», «Бан», «Отклонить».
  Кнопками может пользоваться ранг ≥ 2 этой группы; бот проверяет ранг нажавшего.
- Отдельный чат админов: в группе `репорты в чат` → бот даёт код на 10 минут;
  в чате админов (бот там есть) `репорты сюда <код>` — жалобы идут туда.
  `репорты здесь` возвращает их в группу.
- `репорты` — список открытых.

### База спамеров

- Пополняют только сотрудники сайта: `admin_ids` и `moderator_ids` из config,
  у которых привязан Telegram (`tg_links`: Roblox id ↔ id лички = id в
  Telegram). Модераторы чужих групп в базу не пишут.
- Команды работают в любой группе с ботом и в личке бота.
- `+спамер` в группе: в базу + бан в этой группе. Плюс бан во всех активных
  чатах с включённым фильтром `спамеры`, где бот этого человека видел
  (`cm_members`). Баны в других чатах идут после `tg_finish_response()`, не
  больше 200 чатов за команду (Telegram пускает около 30 вызовов в секунду).
- `-спамер` убирает из базы; баны в чатах не снимает (это решает каждый чат).

### Чистка

- `чистка 50` — `deleteMessages` по id от текущего вниз (до 100 за вызов,
  несуществующие id Telegram пропускает). В ответ на сообщение — от него до
  текущего, тоже не больше 100.
- `чистка @ник` — его сообщения из `cm_msgs` (48 часов: старше бот удалять не
  может).
- `кик удалённых`, `кик неактивных 30 дней`, `кик новых 1ч` — только среди тех,
  кого бот видел (`cm_members`): Bot API не даёт список участников. Перед киком
  бот показывает число и кнопку «Подтвердить». Удалённый аккаунт = в ответе
  `getChatMember` пустое `first_name` или «Deleted Account». Проверки и кики
  идут после `tg_finish_response()`, не больше 200 человек за команду; если
  подходящих больше, бот так и пишет, и команду повторяют.

### Заметки

`#имя` в начале сообщения → бот отвечает текстом заметки с исходным
оформлением (`entities`). Имя — `[а-яёa-z0-9_]{1,32}`, без учёта регистра. До
50 заметок на чат.

### Таймеры

- Время — по Москве, как на сайте. От 1 минуты до 1 года. До 5 активных на чат.
- Тело со второй строки: если оно разбирается как команда — выполняется от
  имени автора, иначе текст публикуется.
- В момент срабатывания ранг автора проверяется заново: снятый модератор не
  выстрелит из прошлого.

## Фильтры и триггеры

### Фильтры

| Имя | Что ловит | По умолчанию |
| --- | --- | --- |
| `спамеры` | человек из `cm_spam` при вступлении или первом сообщении | **вкл**, бан навсегда |
| `ссылки` | любые ссылки, кроме `maknemy.com` и доменов чата; сущности Telegram `url` / `text_link` и обходы из фильтра сайта («evil . ru») | **вкл**, удалить |
| `пересылки` | пересланное из каналов и чужих групп | выкл |
| `мат` | встроенные корни (`words.php`) с исключениями + слова чата | выкл |
| `флуд` | 5 сообщений за 10 секунд или один текст 3 раза подряд; меняется `фильтр флуд N S` | выкл |
| `капс` | от 10 букв, из них ≥ 70% заглавные | выкл |
| `стикеры`, `гифки`, `голосовые` | по типу сообщения; кружки — голосовые | выкл |

- Встроенный список мата — корни с масками и список исключений, чтобы не
  ловить обычные слова («употреблять», «корабля», «рубля», «оскорблять»).
  Исключения проверяются тестами.
- Фильтры не трогают ранг ≥ 1 и админов Telegram.
- Изменённые сообщения проверяются так же, как новые.
- Срабатывает первый подошедший фильтр по старшинству: спамеры → ссылки →
  пересылки → мат → флуд → капс → медиа. Действия разных фильтров не
  складываются.

### Триггеры

- Без триггера фильтр только удаляет сообщение (у `спамеры` — бан).
- Триггер задаёт 1–3 действия из: `удалить`, `варн`, `мут <срок>`, `кик`,
  `бан <срок>`. Пример: `триггер ссылки: удалить, мут 1ч`.
- `-триггер <имя>` — вернуть реакцию по умолчанию; `триггеры` — список.
- `варны` — тоже триггер: что делать на лимите варнов.
- Если действие — варн и он добил лимит, следом срабатывает триггер `варны`.

### Разбор сообщения

1. Запомнить автора: `cm_users`, `cm_members.last_seen`, строка `cm_msgs`.
2. Автор в базе спамеров и фильтр включён → бан, удалить, конец.
3. Команда → выполнить, конец.
4. Автор не исключён → фильтры по старшинству → действия триггера.
5. `#имя` → заметка.

### Вступление

Служебное сообщение `new_chat_members` (на `chat_member` полагаться нельзя: на
бою он до бота не доходит — см. розыгрыши, PR #183; если придёт, разбирается
так же):

1. Спамер из базы и фильтр включён → бан.
2. Есть приветствие и человека ещё не приветствовали → приветствие,
   `greeted_at`. Больше 3 вступлений за минуту — одно общее приветствие на всех.

### Добавление бота в группу

`my_chat_member` со статусом участника или админа → строка `cm_chats` и
короткое сообщение в группе: что бот делает сам (ссылки, спамеры), каких прав
не хватает (удаление сообщений, блокировка) и `помощь`. Убрали бота → `active
= 0`, данные остаются. Группа стала супергруппой (`migrate_to_chat_id`) →
строки чата переезжают на новый id.

### Служебные ответы

- Если триггер только удаляет сообщение (ссылки по умолчанию), бот молчит:
  в живом чате иначе пойдёт поток извещений. Пишет, только когда среди
  действий есть варн, мут, кик или бан.
- Ответы на срабатывание фильтров («🚫 Вася: мат → варн 2/3») и короткие
  подтверждения команд удаляются через минуту (`cm_queue` + cron).
  `автоудаление выкл` это отключает. Списки (`варны`, `правила`, `заметки`) и
  приветствие не удаляются.
- Бюджет: не больше 15 сообщений бота в минуту на группу (Telegram пускает 20).
  Бюджет кончился — бот не пишет, но удаляет и ограничивает дальше.

## Ошибки

| Случай | Поведение |
| --- | --- |
| Нет миграции | `cm_ready()` = false, модуль молчит |
| `cm_enabled` = false | модуль молчит |
| У бота нет прав | одно сообщение в сутки на чат (`rights_warned_at`) с перечнем прав |
| Telegram отказал (цель — его админ, сообщение старше 48 ч) | короткий ответ с причиной |
| Ошибка базы | лог, вебхук отвечает 200, остальная цепочка не задета |
| 429 от Telegram | сообщение не отправляется, повторов из вебхука нет |
| Бота убрали из группы | `active = 0` |
| Группа → супергруппа | перенос на новый `chat_id` |

## Тесты

`tests/cm_*_test.php` на существующем каркасе (`tests/lib.php`, `test_db()` —
SQLite в памяти, DDL таблиц в самом тесте или общем `tests/cm_schema.php`, как
`hunt_schema.php`). В сеть не ходят: `$send` записывает вызовы.

- Разбор: префиксы, `/cmd@бот`, команды без префикса и молчание без ранга, цели
  всех видов, сроки и пределы Telegram, причины.
- Ранги: матрица «кто кого», создатель = 5, передача и возврат, журнал, `дк`.
- Наказания: параметры `restrictChatMember` / `banChatMember`, кик = бан +
  разбан, лимит варнов → триггер, истечение варнов.
- Фильтры: по умолчанию включены только ссылки и спамеры; `maknemy.com` и
  домены чата проходят; мат с двойниками и исключениями; окно флуда; порог
  капса; исключения для рангов и админов; изменённые сообщения.
- Вебхук: группа уходит в модуль, личка, кнопки розыгрышей и `my_chat_member`
  для каналов работают по-старому; ошибка модуля не ломает ответ.
- Cron: таймер выполняется вовремя и перепроверяет ранг; автоудаление;
  очистка `cm_msgs`.
- Бюджет сообщений и молчание при его исчерпании.

## Запуск

1. Мерж PR → деплой.
2. phpMyAdmin: миграция `docs/migrations/2026-11-07-chat-manager.sql`.
3. BotFather → `/setprivacy` → **Disable**. Telegram применяет это к группе
   только после того, как бота удалят и добавят заново — в «Башне Шута» тоже.
4. `/admin/support` → «Подключить вебхук» ещё раз (`edited_message`,
   `max_connections`).
5. Cron в cPanel раз в минуту: `api/cm_cron.php`.
6. Проверка в тестовой группе: мут, ссылка, `+спамер`, заметка, таймер.
7. Описание — `docs/chat-manager.md` (как `docs/telegram-notify.md`).

## Не входит

- Голосование за бан, сетка чатов, каталог, клоны бота, бизнес-бот, инлайн.
- Индивидуальные исключения доступа для отдельных людей.
- Фильтры по возрасту аккаунта, репутации, Telegram Premium.
- Статистика, профиль, репутация, награды — этап 2.
- Игры и отношения — этап 3.
- Экономика.
