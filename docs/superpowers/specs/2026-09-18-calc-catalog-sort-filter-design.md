# Каталог калькулятора: порядок по значку и фильтр как в тирлисте

**Дата:** 2026-09-18
**Ветка:** `feat/calc-catalog-sort-filter`

## Задача

Каталог калькулятора (`#tcCatalog`) показывает предметы в порядке тирлиста:
тир за тиром, внутри тира по цене. Для глаза это «по цене вперемешку»: CR,
PM, CS, VH, MS, PM… Владелец просит:

1. Порядок по значку: сначала фрукты (по цене), потом скины и мутации, потом
   пермы.
2. Фильтр в каталоге, как в тирлисте.

## Решения владельца

- Порядок значков: **FR → CS → CM → MS → CR → PM → GP → VH**, внутри значка —
  по цене, дороже выше. Хроматики (CR) стоят со скинами: в тирлисте они тоже
  входят в «Конфигураторы». Пассы и ваучеры в задаче не упомянуты и уходят в
  конец.
- Фильтр — **как в тирлисте**. Из трёх показанных вариантов отклонены
  выезжающий из плашки «Каталог» список из макета Figma (`238:1590`, фрукты ·
  скины · пермы · мутации · пассы · ваучеры · все, выбор одной категории) и
  кнопки тирлиста с выбором одной группы.

## Порядок (`js/calc.js`)

- `CATALOG_ORDER = ["fr", "cs", "cm", "ms", "cr", "pm", "gp", "vh"]`.
- `sortCatalog(items)` возвращает новый массив, вход не меняется. Ключи по
  очереди: место `badgeCodeFor(item.type)` в `CATALOG_ORDER`, `itemValue` по
  убыванию, исходный индекс (порядок тирлиста). При равной цене порядок
  тирлиста сохраняется.
- Цена та же, что калькулятор складывает (`itemValue`). Нечитаемое значение
  считается 0 и уходит в конец своей группы. На бою у Eagle Fruit стоит «0,4»
  с запятой: `parseValue` её намеренно не читает (тест `'1,234'` — мусор), так
  что предмет встанет после Dark Fruit 0.3 и в сумме даёт 0. Правится данными
  в админке, не кодом.
- Группа берётся через `badgeCodeFor`, то есть по значку на карточке: значок и
  место карточки не могут разойтись. Неизвестный тип — FR, как и его значок.
- Сортировка один раз в `applyTierlist` (загрузка и каждое обновление
  тирлиста). `catalogIndex` и ссылки `?l=&r=` не затрагиваются.

## Фильтр

Группы и логика — как в тирлисте (`groupOf`, `FILTER_KEYS` и обработчик
`#filters` в `app.js`):

| Кнопка | Значки |
|---|---|
| Фрукты | FR |
| Конфигураторы | CS, CM, MS, CR |
| Пермы | PM |
| Пассы | GP, VH |
| Все | включает все четыре группы |

- Кнопка группы включает и выключает её. Последнюю включённую выключить
  нельзя, нажатие ничего не меняет — как в тирлисте.
- «Все» подсвечена, когда включены все четыре группы.
- При загрузке страницы включено всё. В тирлисте пермы по умолчанию скрыты, но
  в калькуляторе без них не собрать сделку.
- Выбор живёт, пока открыта страница: следующее открытие каталога его
  сохраняет, перезагрузка сбрасывает. В `localStorage` не пишем.
- Фильтр и поиск складываются по «И»: поиск идёт внутри включённых групп.
  Ничего не нашлось — «Ничего не найдено», как сейчас.
- Смена фильтра перерисовывает сетку сразу, без задержки поиска, и
  прокручивает её в начало.
- Кнопки идут в порядке карточек: Фрукты, Конфигураторы, Пермы, Пассы, Все
  (в тирлисте Конфигураторы первые).

### Чистые функции в `calc.js`

Тестируются в node, DOM не трогают (тест «calc.js не трогает DOM»).

- `FILTER_GROUPS = ["fruits", "configurators", "perms", "passes"]`.
- `filterGroupOf(type)` — группа по значку.
- `allFiltersOn()` — `{ fruits: true, configurators: true, perms: true, passes: true }`.
- `toggleFilter(filters, key)` — новый объект: `"all"` включает всё; группа
  переключается; если выключилась последняя, возвращается прежнее состояние.
- `filterCatalog(items, filters, query)` — включённые группы и поиск по имени
  (регистр не важен, пробелы по краям отрезаются). Поиск переезжает из
  `calculator-page.js` без изменения логики.

### Разметка (`calculator.php`)

В `.tc-cat-sub`, между плашкой «Каталог» и ✕:

```html
<div class="tc-cat-filters" id="tcCatalogFilters" role="group"
     data-i18n-label="news.filterGroupLabel" aria-label="Фильтр по категориям">
  <button type="button" class="chip" data-f="fruits" data-i18n="filters.fruits"
          data-i18n-title="filters.fruitsTitle" title="Обычные фрукты" aria-pressed="true">Фрукты</button>
  <button type="button" class="chip" data-f="configurators" data-i18n="filters.configurators"
          data-i18n-title="filters.configuratorsTitle" title="Скины, мутации, конфигурации и хроматики"
          aria-pressed="true">Конфигураторы</button>
  <button type="button" class="chip" data-f="perms" data-i18n="filters.perms"
          data-i18n-title="filters.permsTitle" title="Перманентные фрукты" aria-pressed="true">Пермы</button>
  <button type="button" class="chip" data-f="passes" data-i18n="filters.passes"
          data-i18n-title="filters.passesTitle" title="Геймпассы и воучеры" aria-pressed="true">Пассы</button>
  <button type="button" class="chip all" data-f="all" data-i18n="filters.all"
          data-i18n-title="filters.allTitle" title="Показать всё" aria-pressed="true">Все</button>
</div>
```

Запасные тексты в разметке — русские значения из `i18n.js`; при старте
`applyLang` всё равно перепишет их на выбранный язык.

- Тексты — готовые ключи `filters.*`, RU и EN в `i18n.js` уже есть. Подпись
  группы — готовый `news.filterGroupLabel` («Фильтр по категориям» /
  «Filter by category»). `i18n.js` не трогаем: он общий для всех страниц,
  его правит открытый PR #70, а новый ключ потянул бы подъём `?v=` везде.
- Состояние кнопки — `aria-pressed`, а не класс `active`.
- Комментариев в разметку не пишем (правило `public_html`).

### Вид (`calculator.css`)

- Кнопки как `.toolbar .chip` тирлиста: Bebas Neue / Oswald, верхний
  регистр, без фона и рамки; включённая — градиент `#61b5e9 → #2d4aed` и
  кольцо `rgba(136, 176, 255, .32)`; hover — лёгкая подсветка; видимый
  `:focus-visible`.
- Больше 900px: одна строка «Каталог | кнопки | ✕».
- До 900px: кнопки отдельной строкой во всю ширину под «Каталог» и ✕. Если не
  влезают, листаются вбок без полосы прокрутки, как фильтры тирлиста на
  телефоне. Размеры подбираются замером, чтобы на 390px все пять влезали без
  прокрутки.

## Чего не трогаем

Тирлист и его фильтры, `i18n.js`, слоты, счёт, ссылки `?l=&r=`, вид
карточек. Логика поиска та же, меняется только место, где она живёт.
