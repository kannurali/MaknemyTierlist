# Розыгрыши — дизайн

2026-10-14. Запрос владельца: вкладка «Розыгрыши» в админке, описание с
форматированием и картинкой, условия — подписка на Telegram-каналы с
проверкой ботом, бот пишет всем о старте и победителю о победе, участие
только после входа, отдельное всплывающее окно на страницах сайта, страница
со всеми розыгрышами.

## Решения владельца

| Вопрос | Ответ |
| --- | --- |
| Кто выбирает победителя | Кнопка «Разыграть» в админке после конца, случайно |
| Призы | Список: у каждого приза своё число победителей (1 приз / 1 победитель — частный случай) |
| Окно | На каждой странице, кроме главной; снова каждые 10 минут, пока человек не участвует |
| Telegram | Обязателен всегда: без бота не проверить подписку и не сообщить о победе |
| Где живёт розыгрыш | Окно + страница `/giveaways` |
| Условия | Только подписка на Telegram-каналы; условий может не быть |
| Старт и рассылка | По кнопке «Опубликовать»; рассылка всем подключившим бота, мимо переключателей профиля |
| Выдача приза | Владелец пишет победителю сам; бот только поздравляет |

## Устройство

- **Данные** — свои таблицы `giveaways`, `giveaway_entries`, `tg_channels`
  (`docs/migrations/2026-10-14-giveaways.sql`). В `state` ничего не кладётся.
  Статус `draft → live → drawn`; «закончился, ждёт розыгрыша» — это `live`
  с `ends_at` в прошлом, а не отдельный статус.
- **Логика** — `api/lib/giveaway.php`. Эндпоинты: `api/giveaways.php`
  (публичный GET, LSCache 30 с, тег `giveaways`), `api/giveaway_enter.php`
  (участие, 30 нажатий в час), `api/giveaway_admin.php` (админка, сбрасывает
  тег после изменений).
- **Описание** — блочная модель новостей (`news_blocks`), только абзацы,
  цитаты и списки. Свой компактный редактор в `js/giveaway-admin.js`
  (contenteditable → блоки), редактор новостей не тронут. Пустой EN
  переводит Google при сохранении; неизменённые абзацы берут EN из прежней
  версии (`gw_reuse_en`), чтобы не гонять переводчик на каждом сохранении.
- **Каналы** появляются сами: вебхук получает `my_chat_member`, когда бота
  делают админом канала. Ссылка «Подписаться» — `t.me/<username>` или
  приглашение от `exportChatInviteLink` для приватного канала.
- **Подписка** — `getChatMember(канал, chat_id из tg_links)`. Проверяется при
  участии и ещё раз при розыгрыше. Telegram не ответил — участие отвечает
  `tg_down`, розыгрыш не записывается вовсе («не смог проверить» ≠ «проиграл»).
- **Один Telegram — одно участие**: уникальный ключ `(giveaway_id, chat_id)`.
- **Розыгрыш**: участники перемешиваются (`random_int`), призы по порядку
  раздаются первым подходящим (не забанен, бот подключён, подписан). Один
  человек — один приз. Повторно разыграть нельзя.
- **Окно** — `js/giveaway-pop.js` + общая карточка `js/giveaway.js`
  (её же рисуют страница и предпросмотр в админке). Через 2 с после загрузки,
  повтор — через 10 минут после последнего показа (`localStorage
  nx-gw-seen-v1`). Где человек уже участвует, говорит `api/session.php`
  (поле `giveaways`); шапка отдаёт сессию событием `mk:session`, второго
  запроса нет. Пока открыто окно розыгрыша, рекламное окно не открывается.
- **Вход из окна** возвращает на ту же страницу и сразу продолжает участие
  (`sessionStorage nx-gw-resume-v1`). Нет бота — окно выдаёт ссылку на бота и
  само ждёт привязку.

## После мержа на бою

1. Выполнить `docs/migrations/2026-10-14-giveaways.sql`.
2. `/admin/support` → «Подключить вебхук» (Telegram начнёт присылать
   `my_chat_member`).
3. Добавить бота администратором в каналы, подписку на которые проверять
   (для приватного канала — с правом приглашать пользователей).

## Что не сделано намеренно

- Нет пункта «Розыгрыши» в шапке: на телефоне разделы стоят листом 2×3
  (PR #143), седьмой пункт ломает сетку. Вход — окно, кнопка в Telegram и
  sitemap.
- Нет выбора шрифта в описании: модель блоков знает жирный, курсив,
  подчёркнутый, зачёркнутый, спойлер и ссылки; новый шрифт — правка общей
  модели с новостями.
